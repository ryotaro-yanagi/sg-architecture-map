# Location Character — implementation pilot

SGM's current-location marker now renders the architecture-derived soft character whenever the user presses the normal locate control and grants geolocation permission. This is the production implementation. The Character Lab remains a separate experiment. A static red marker is used only if the new SVG controller unexpectedly fails.

## iPhone production verification

1. Open the regular SGM site at `/en/` or `/ja/` on iPhone.
2. Tap the current-location arrow and grant geolocation permission.
3. The **Steps / Ochre / Shadow** character appears at the actual device location; no query parameter is required.
4. Zoom the map to check sizes 20–40px and, after a natural pause, observe occasional form changes.
5. Test Day/Night and backgrounding the app. Day uses a soft shadow; Night uses no shadow.


The character uses the position produced by `navigator.geolocation.getCurrentPosition()` in `src/App.tsx` and the pre-existing `maplibregl.Marker({anchor:'center'})`. All animation happens **inside** the anchored SVG and never modifies the MapLibre GPS anchor.

The new marker is enabled by default. No additional location data requests are made; geolocation still happens only after pressing the locate button.

## Design baseline

- Initial silhouette: **Steps** (Kampung Admiralty abstract reference).
- Additional silhouettes: **Long**, **Rise**, **Sway**.
- Color: **Warm Ochre #E9C77D**; edge: restrained ambient shadow; eyes: off-white sclera plus dark pupils.
- First expression: slight **Look**.
- Scale: existing interpolation with stops `9:20`, `11:23`, `13:28`, `14:32`, `16:37`, `18:40` (CSS px).
- 16px optical corrections are taken from the same geometric data as Character Lab.
- A direct silhouette morph is generated by sampling each SVG outline at 72 perimeter points and interpolating matching points; 760ms ease-in-out, with a soft blink through the midpoint.
- Hold between form changes: randomized 45–90 seconds. Gaze changes more gently.
- Small, natural blink approximately 1.1s after the marker first appears, then randomly every 10–19 seconds.
- Tapping the marker produces a 230ms blink with a slight squash; the 44px touch target does not alter the character size or its GPS anchor. Enter/Space keyboard activation is supported.
- A reserved `onActivate` callback will later allow the same marker tap to open a personal visits/record panel. No such panel or data collection is added in this release.
- `prefers-reduced-motion` prevents automatic morph, gaze and blink animations. Backgrounding the app also stops active animations; focus restoration resumes only from a stable form.
- A measurement failure results in a **static Steps** character instead of hiding the marker.

## Separation & QA

- Shared design data: `src/locationCharacterShapes.ts`.
- Map-only Character Lab: `src/characterLab.ts`.
- Production-marker animation controller: `src/locationCharacter.ts`.
- Real geolocation entry point: `src/App.tsx`, which preserves the existing location permission request and centered MapLibre marker.
- Tests: `npm run test:location-character`, automatically included in GitHub PR validation.

Check (1) geolocation consent and denial, (2) repeated taps of the location button, (3) 20/32/40px size, (4) Day and Night, (5) background/foreground switching, (6) reduced motion, (7) marker tapping versus clicking architecture pins, (8) opening blink and later ambient blinks, and (9) keyboard interaction.

## Deliberate limitations

The 72-point morph is an engineering prototype, not final curve optimization. The exact intermediate silhouette must be evaluated on mobile, especially Steps ↔ Sway. Color and shadow contrast need further on-map review. The Preview has no cloud storage of location data, but the normal browser geolocation permission still applies. The app does not transmit coordinates to our prototype controller.

Rollout follows merge of PR #17 and successful GitHub Pages deployment. If visual QA finds a regression, revert the feature commit.
